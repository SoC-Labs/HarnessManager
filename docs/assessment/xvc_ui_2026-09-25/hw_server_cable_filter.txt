# XVC-UI: hw_server opens the XVC cable only (david's scope rule: never whole-device JTAG)
# 2026-09-24/25, host srv03335, 127.0.0.1 only; no board, no cable, no hub.
#
# The flag: hw_server has no "disable USB" switch. Its cable settings (xsdb `configparams`
# on a running 2024.1 hw_server) are:
#   auto-open-servers  "set to select types of JTAG cables to detect"   default "*"
#   jtag-port-filter   "JTAG port filter list"                           default ""
#   always-open-jtag   "set to open JTAG cables even without clients"    default 0
#   auto-open-ports    "set to automatically open any detected JTAG ports" default 1
# The default "*" opens digilent-ftdi, xilinx-ftdi, xilinx-pcusb, bscan-jtag
# (2026.1 adds amd-uniflashpod): a USB JTAG cable on the HM host would be offered.
#
# HM's argv (services/xvc.py hw_server_argv) now sets both:
#   -e "set auto-open-servers xilinx-xvc:127.0.0.1:<R>"      replaces "*" with the one XVC server
#   -e "set jtag-port-filter Xilinx/XVC/127.0.0.1:<R>"      hides any other cable, even one a
#                                                           client opens later (jtag servers -open)
# jtag-port-filter is a substring match on the port name "<maker>/<product>/<serial>"
# (probed: "Xilinx", "XVC", "127.0.0.1:<R>" and "Xilinx/XVC/127.0.0.1:<R>" admit the XVC
# cable; "*", "Xilinx/127.0.0.1:<R>", "xilinx-xvc:..." and "Xilinx/nomatch" admit none).
# The full name admits the relay's port only.
#
# Result (below): with HM's argv, 2024.1, 2025.2 and 2026.1 all find debug_bridge
# (idcode 0a003093 irlen 6) on the XVC cable; a second XVC cable a client opens shows
# "cables 0" (filtered); `nomatch` shows the parameter is live. The "old" argv (before
# this lane) already replaced "*", but let a client open more cables.
#
# UNVERIFIED against a physical USB cable until the board window: this host has no USB
# devices (lsusb: two USB/IP root hubs only), so digilent-ftdi reports "cables 0" in
# every run, filter or not. Check at the window: on a host with a Digilent/Xilinx USB
# cable plugged in, `xvc open`, then xsdb `jtag servers` / Vivado `get_hw_targets` on
# HM's hw_server must list the XVC cable only.
#
# Reproduce: PYTHONPATH=src:. python -m tests.spikes.xvc_hw_server_filter_spike --vivado-bin <bin>
